RUDP Demo Runbook

Run each part of the project, in review order. Commands run from the project folder (cd rudp) in WSL or Linux.

0. Setup

Do this once, before you walk in.

  1. Get the code and build everything.

    git clone https://github.com/Capsturrrr/rudp && cd rudp
git pull
make && make smart chat

  2. Check the three programs exist.

    ls bin

    You should see server client smart_client chat.

  3. Open the slides, Packet Tracer file and Wireshark in separate windows so you only switch, not launch.

Open the web chat with http://, not https://, or Chrome shows ERR_SSL_PROTOCOL_ERROR.

1. Base RUDP with packet loss

Show handshake, data, ACKs, retransmission and the congestion window.

  1. Terminal 1: start the server.

    ./bin/server

  2. Terminal 2: run the client with 10% simulated loss.

    ./bin/client 10

  3. Point at the log: SYN/SYN-ACK, ACK … cwnd=, slow start turning into congestion avoidance, ssthresh dropping after a loss, and the final line "All 62 packets delivered".

Say: every packet is numbered and checksummed; lost ones are resent; the window grows after each ACK and halves on loss.

2. AIMD vs Smart-RUDP

Run the same lossy path with both window controllers.

  1. Terminal 1: build and start a server on its own port.

    gcc -DSERVER_PORT=9301 -o bin/server_9301 src/server.c src/common.c
./bin/server_9301

  2. Terminal 2: AIMD baseline.

    ./bin/smart_client --mode aimd --port 9301 --delay 25 --jitter 10 --loss 2 --rate 800 --queue 50 --packets 500 --seed 3 --qfile results/q_lossy.txt --train 0 --emu 1

  3. Same command with the learned controller.

    ./bin/smart_client --mode rl --port 9301 --delay 25 --jitter 10 --loss 2 --rate 800 --queue 50 --packets 500 --seed 3 --qfile results/q_lossy.txt --train 0 --emu 1

  4. Read the RESULT line: the fourth value is time in ms, then packets sent and retransmissions.

One seed on one path is an illustration only. If asked who wins in general, quote the experiments (Section 8: tied on lossy, slower on 5G-like and satellite-like) and the 48-path chat stress test.

3. Terminal chat

Two people messaging over RUDP packets.

  1. Terminal 1.

    ./bin/chat 7001 127.0.0.1:7002 Harsh 20

  2. Terminal 2.

    ./bin/chat 7002 127.0.0.1:7001 Rohit 20

  3. Wait two seconds after both start, then type in each. The last number (20) is simulated loss in percent; the status line shows sent, dropped and retransmitted counts.

Typing before the connection is up is the usual reason a first message looks lost. Wait for the NAT punch.

4. Web chat on one machine

The browser version, with the loss slider and controller switch. This is the main live demo.

  1. Terminal 1: first participant.

    python3 web/rudp_web.py --udp 9001 --peer 127.0.0.1:9002 --name Harsh --http 8080 --loss 10 --delay 40

  2. Terminal 2: second participant.

    python3 web/rudp_web.py --udp 9002 --peer 127.0.0.1:9001 --name Rohit --http 8081 --loss 10 --delay 40

  3. Open both pages side by side.

    http://localhost:8080
http://localhost:8081

  4. Send a message each way. Drag the loss slider and watch the resent counter and the log.

  5. Pick Fixed, click "Send 60 test messages", note the time. Repeat with AIMD, then Smart-RUDP.

Expected on this path: about 0.8 s fixed, 1.8 s AIMD, 0.7 s Smart-RUDP. Numbers vary run to run; the ordering is what to show.

5. Laptop and phone over the internet

Two real devices on different networks, linked by Tailscale.

  1. Both devices: install Tailscale, sign in with the same account, and check both show as connected. Note each device's 100.x address.

  2. Laptop (point at the phone's address).

    python3 web/rudp_web.py --udp 9001 --peer PHONE_100.x.x.x:9001 --name Harsh --http 8080

  3. Phone (Termux; point at the laptop's address).

    cd rudp && git pull
python3 web/rudp_web.py --udp 9001 --peer LAPTOP_100.x.x.x:9001 --name Rohit --http 8080

  4. Open http://localhost:8080 on each device and chat.

If WSL sits behind Windows and nothing connects, install Tailscale inside WSL too. Keep a screenshot of this working as a fallback.

6. Network: Packet Tracer and Wireshark

The routed four-router OSPF network and the packet capture.

  1. Packet Tracer: open the saved .pkt. Show the topology, then show ip route on R1 (OSPF routes).

  2. Failover: shut R1 Gi0/2, run a ping across, and show only 1 of 71 pings lost while traffic reroutes through R2.

  3. ACL: ping the staff PC from the student PC and show "destination unreachable".

  4. Wireshark: load the dissector, then open a capture.

    wireshark -X lua_script:network/rudp.lua network/smart_lossy_aimd.pcap

  5. Apply a display filter.

    smartrudp.flags.data == 1

    Steps for the sequence-time graph are in network/WIRESHARK_STEPS.txt.

7. Show the AI agent and the stress test

The code, the learned table, and the evidence.

  1. Open the agent source and point at the state, the choose function and the update line.

    src/rl_cc.h
src/smart_client.c
web/cc.py

  2. Show the learned Q-values (80 rows, 5 actions).

    head -20 results/q_chat.txt

  3. Run the stress test (about a minute on 2 CPUs; skip it live and quote the result if short on time).

    python3 web/stress.py results/q_chat.txt

  4. Switch the chat to the neural agent: pick "Smart-RUDP (deep, neural net)" in the dropdown (the file results/dqn_chat.json is loaded automatically).

  5. Retrain from scratch, only if asked.

    python3 web/train.py
Result to quote: 48 unseen random paths, mean 3.73 s Smart-RUDP vs 7.16 s AIMD; faster on 27, slower on 5, within 5% on 16. Simulated. It is tabular Q-learning, not deep RL.

8. Extra evidence

Baselines, selective ACK, reordering and confidence intervals. Each prints a table in about a minute.

  1. Plain UDP and a TCP model on the 48 unseen paths.

    python3 web/baselines.py

  2. Go-Back-N versus selective acknowledgment.

    python3 web/sack_test.py

  3. Reordering under jitter.

    python3 web/reorder_test.py

  4. Confidence intervals for the C experiments (the full run takes about 30 minutes; show the saved results instead).

    python3 ci_summary.py

  5. Real TCP, UDP and RUDP on netem (Linux only, needs sudo).

    sudo bash netem_baselines.sh lossy
The TCP result is a model, not kernel TCP. Say so before she asks.
